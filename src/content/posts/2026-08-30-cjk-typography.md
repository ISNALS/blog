做这个博客时，我在排印上花的时间比动效多。原因很朴素：**读者 99% 的时间在读字，1% 的时间在看动效。**

而中文排印有几个默认值，如果不去管它，页面就是会"说不出的不对劲"。

## 一、行高不是 1.5

CSS 默认 `line-height: normal` 对中文来说太挤。常见的建议是 1.5，但那是为英文定的——英文有小写字母的 x-height 和升部降部，视觉上的"行"比中文矮。

中文是方块字，字面高度就是字号本身。**同样的行高数值，中文读起来比英文挤得多。**

我的取值是 **正文 1.85**。这不是玄学：方块字需要在行与行之间留出足够的"空白通道"，眼睛才能稳定地从行尾折回下一行的行首。

```css
.prose { line-height: 1.85; }
```

## 二、中西文之间要有一个空格的距离

看这行：`用 GitHub Actions 自动构建`

如果直接写 `用GitHub Actions自动构建`，中文和拉丁字母贴在一起，视觉上会挤成一块。传统做法是手动加空格，但那样在源码里很难看，而且换个字体就错位了。

正确做法是**用 CSS 在渲染时加**：

```css
/* 用 letter-spacing 之外的技巧：给混排处补一个 1/4 em 的间距 */
.prose { text-spacing-trim: space-all; }
```

`text-spacing-trim` 是新的 CSS 属性，Chrome 与 Safari 已支持；不支持时退回手动空格。**关键认识是：中西文间距是排印问题，不是内容问题**——所以它不该由作者在正文里手动维护。

## 三、标点不是占满一格的

中文标点是全角，一个逗号占一格。但视觉上它只该占**半格**——因为标点周围本来就该有空白。

这就是"标点挤压"（punctuation kerning）。行首的引号、行尾的句号，都应该吃掉半个身位：

```css
.prose {
  line-break: strict;          /* 避免标点出现在行首 */
  hanging-punctuation: allow-end;  /* 行尾标点可以溢出 */
}
```

不开这个，右边界会出现"锯齿"——因为有的行最后跟一个句号，有的行不跟，而句号是全角。

## 四、字距要收，字号要放

标题上的反直觉操作：**越大的字，字距越要收**。

道理是：字号变大时，字与字之间的绝对距离同步变大，而人眼感知的是**相对**比例。所以同样 0 的字距，在 16px 下显得紧，在 96px 下显得散。

```css
h1 { font-size: clamp(2.6rem, 1.9rem + 3.2vw, 5.2rem); letter-spacing: -0.03em; }
```

我这站的刊头就是这个取值：**字号越大，letter-spacing 越负**。

## 五、还有一件事：别用 `text-align: justify`

中文两端对齐看起来"整齐"，但它会为了填满行宽而**随机拉伸字距**。结果是每一行的字距都不一样，读起来像被揉过。

左对齐 + 合理的行宽（40–50 个汉字）比两端对齐好得多。

## 收尾

排印这件事最麻烦的地方在于：**做得对的时候没人会注意到。**

没人会说"这个站的行高很舒服"，但每个人都会在行高不对的时候觉得"这站有点糙"。这大概就是基本功的定义——它的成功标志是隐形。
